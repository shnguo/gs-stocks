# 20万元业绩实验：统计诊断与样本可达性

目前仍未建立可收费的稳定收益优势。新增的是研究统计层及其独立复算，没有运行合格真实收益实验，也没有启动正式前瞻。佣金万分之五已确认；最低佣金5元与10%回撤仍是研究假设。

## 方案发现：一年样本门槛与持仓约束不相容

原方案要求6槽位、正常持有20日、252日唯一正式检验，以及至少100个成熟公司×报告期事件。若收益证据按实际买入且完成主要窗口的独立事件计数，正常持仓下不能在一年中达到100笔。

计数约定为：第0日收盘冻结，最早第1日开盘买入，第21日开盘完成20日窗口；同一槽位当日可以开盘卖出并接受此前已冻结的替换。没有提前风险退出时，成熟笔数上界为6乘以向下取整的（观察日数减2）除20。

| 观察交易日数 | 正常20日持仓的成熟笔数上界 | 说明 |
| --- | ---: | --- |
| 120 | 30 | 只作运营审查 |
| 252 | 72 | 小于原100事件门槛 |
| 342 | 102 | 仅是达到100笔所需日数的理论下界，不保证60个成熟入场日期 |
| 504 | 150 | 仍受信号稀疏、匹配、受阻成交和独立报告期数限制 |

这里不是所有路径的绝对上界：强制风险退出可能提前释放槽位，受阻退出则可能减少笔数。验证方案不应依赖大量强制提前退出才能凑样本。100个没有实际买入的候选也不能代替100笔收益证据。原方案的“成熟事件”需要在注册前明确为实际成交计数，不能在看到结果后另换分母。

实际六槽位合成账本复算了252日情景：买入78笔，其中72笔完成窗口，末尾6笔留在账户估值；满仓成批替换的人工情景只有12个成熟入场日期。12不是实际策略的日期上限。该情景假定无限合格机会并使用人为公司/报告期身份，只验证持仓和统计程序。

用户随后明确选择保留100事件并改为504日。当前v2已另存并实现唯一504日区间；100事件、60日期保持原值，稳定性按八个63日区间至少六个为正延续旧比例。原v1和本文件以下早期审计结果保持历史含义，最新实施与证据见earnings-validation-v2-20261012.md；尚未完成正式注册。

## 新增实现

src/quant_research/earnings_validation.py接收三个情景，每个情景包含完整E1账户、已匹配子集E1账户和价格对照账户。基础、双佣金/滑点及延迟一日的账户分别核对资金、持有期和情景身份，先从成交、持仓及分红重建净值，再计算收益。它要求外部提供完整观察交易日列表；缺现金日、日期不齐、非数值收益或伪造日收益都会拒绝。

完整E1用于绝对收益与回撤关口。主要增益使用相同冻结配对的E1子集与P_matched_exposure比较，避免将完整E1与较小对照组合混算。未匹配事件仍留在完整账户。匹配覆盖按开盘结果揭晓前的选中预算计算；单边成交、单边持仓与双方现金继续留在逐日账户，计划匹配不自动获得实际暴露相等的资格。

主要指标为252倍每日账户净收益差的平均数。两侧总收益和CAGR分别披露；CAGR之差不能替代主指标。自助法草案明确为不循环的移动日期块：长度20、重复10000、固定种子20261012；两侧使用同一索引，最后一块截到原日数，采用95%百分位区间与线性分位数。它与[arch的移动块方法说明](https://arch.readthedocs.io/en/latest/bootstrap/generated/arch.bootstrap.MovingBlockBootstrap.html)采用相同的不环绕块定义，但本实现没有依赖或调用arch。区间只在输入长度恰好为原设计252日时生成；120日没有区间或晋级。

成熟数从真实买入记录连接预先冻结的交易、公司与报告期身份，满20个实际观察交易日才计数；没有成交的候选、不成熟持仓及同一公司同一报告期重复入场不能增加成熟数量。末尾未完成持仓仍影响完整账户净值。

稳定性与最优五笔剔除在原方案中尚有实现歧义，本研究实现明确暴露以下草案，须在评价前注册：

- “四季度”暂按连续四段各63交易日统计，不能称日历季度；更长正式观察期需要重新定义稳定性关口，本模块不会把504日自动拆成四个126日“季度”并接受。
- 在成熟且实际成交的匹配E1中按期末净损益元排序，取最盈利五笔，平局按交易ID。同步扣除这五笔及各自冻结对照的逐日累计净损益，腾出的资金留现金，其余交易不缩放、不重新挑选。少于五笔则此诊断不可得；未成熟事件继续留在净值。

统计模块所有输出仍标记正式收益资格为false，即使数值关口全部通过。它未实现不可撤销的单次正式检验登记，不能阻止调用方反复选窗；完整来源验收、独立人工数值核对、实际最低佣金、环境封存及及时运行器仍是外部必需条件。

## 可复现证据

scripts/audit_earnings_statistics.py使用新建目录运行，保存实际人工输入、冻结身份/配对、各情景逐日净值/成交/持仓与输出哈希，不覆盖旧审计。当前产物为artifacts/earnings-validation-20261012/statistics-audit-v2/audit.json；v1保留首次12项新增测试时的来源绑定。

| 核对 | 结果 | 结论边界 |
| --- | --- | --- |
| 原始买入成交逐笔独立计数 | 78笔买入、72笔成熟 | 只验证人工满容量持仓约束 |
| 120/252/342/504日逐笔枚举与公式 | 全部一致 | 不是实际信号数量预测 |
| 非零人工日收益、10000次独立循环复算 | 区间端点最大绝对差约5.6×10的负17次方 | 验证算法，不证明统计假设适用于市场 |
| 账户、配对、筛选、端到端与新统计层 | 50项定向测试通过，其中新增15项 | 工程验证，未重跑Rust或整个仓库 |
| 人工平价行情中的基础与对照增益 | 0 | 双方相同人为价格与费用的预期算术结果 |

人工平价情景的完整账户因手续费与滑点而亏损，是成本测试用例，不能引用为真实策略收益或策略无效的证据。本轮没有产生新的真实历史合格信号，也没有增加实际前瞻成熟日期。

后续优先顺序仍是完善首次版本与完整覆盖来源、取得独立数值与执行资料验收，再把已验证的研究账户和统计模块接入封存协议的正式运行器。当前有效结论是：现有证据不足以支持稳定收益收费，并且原一年样本目标需在注册前处理。
