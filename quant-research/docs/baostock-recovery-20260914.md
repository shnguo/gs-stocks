# BaoStock 连接故障处理

2026-09-14 的历史换手率/估值采集失败发生在登录前后，尚未到行情字段查询。现有训练数据与已完成的模型实验未改动。

## 定位证据

- 官方 SDK 0.9.3 与本地诊断使用同一主机 public-api.baostock.com、端口 10030，登录报文字节哈希完全相同。
- 本机 DNS 与向 1.1.1.1 查询均返回 114.94.20.42。系统 HTTP/HTTPS/SOCKS 代理关闭，无代理环境变量。
- 官方 SDK 独立登录也失败，返回 10002007 网络接收错误。
- 有的连接在 TCP 阶段超时；成功建连的一次，等待登录响应 45 秒仍为零字节。
- 官方旧 SDK 0.8.9 的 www.baostock.com:10030 也建连超时；官网 HTTPS 返回 200。
- 加入阶段记录后的实际采集先收到登录连接重置，随后收到 TCP 连接拒绝。不能据此断言是全网服务故障、运营商路由还是服务端限流；没有收到需要 API key、付费或其他身份验证的拒绝消息。

证据目录 artifacts/baostock-recovery-20260914-v1，包含官方包及其 PyPI 哈希、源代码、DNS/连接探测、官方 SDK 错误、长等待零字节回执和字节一致性验证。[官方 SDK 来源](https://pypi.org/project/baostock/)。

## 已实现修复

Rust 采集回执新增连接阶段、登录阶段、查询阶段和校验阶段的错误归属，以及实际远端地址和网络错误是否可重试。macOS 的 WouldBlock 超时会以明确的 TimedOut 错误呈现，并附带等待时间与已收到字节数。网络 EOF 与总截止时间也以正确的网络错误类型处理。

新增受控恢复入口，每个请求最多三次，等待间隔 5 秒、15 秒。每次尝试使用独立目录；成功回执明确引用采用的尝试，所有旧错误和部分响应继续保留。只重试网络超时、重置、中断、临时连接拒绝及提前断开；服务端业务拒绝、协议与数据校验失败直接停止，不会无限循环。

历史特征小样本入口已经使用该恢复流程。独立验证器检查恢复任务必须完成、选中尝试必须成功、尝试哈希与请求一致，然后重新解析原始数据。它不能把失败任务或零行的失败回执当成成功数据。

首次受控线上尝试 artifacts/daily-feature-pilot-20260914-v2 保留两次错误：登录重置、TCP 拒绝。发现临时连接拒绝尚未纳入限次重试后，已补入并增加相应阶段回归验证；后续新尝试不覆盖 v2。

本地校验：BaoStock 协议测试 12 项、采集会话/恢复测试 4 项、Python 原始回放与恢复任务拒绝测试 4 项通过；锁定依赖构建通过。线上恢复是否成功以新的完整采集与独立回放结果为准。

## 线上最终复查

09:16 UTC，artifacts/daily-feature-pilot-20260914-v3 的三次尝试全部在 TCP 建连阶段收到连接拒绝，限次恢复按预期停止。失败尝试的原始回执和清单哈希已重新核对，结果汇总为 artifacts/baostock-recovery-20260914-v1/conclusion.json。

客户端错误分类、回执留存与恢复逻辑已修复；线上行情数据采集仍未恢复，不能声称 BaoStock 问题已完全解决。继续定位需要一条现有可用的其他网络出口，或端点本身恢复服务。未更改系统网络设置、替换训练数据或启动新模型训练。

## 出口对照补充

随后发现本机已有 127.0.0.1:1080 SOCKS 代理。只读取其路由类型与出口标识，没有输出或复制代理凭据，也没有修改或重启代理。该代理访问 PyPI HTTPS 成功返回 200；经代理查询 Google DNS，BaoStock 仍解析为 114.94.20.42。通过代理的 BaoStock 登录则在约 3.7 秒后收到 EOF，零响应字节。

因此现有出口对照已完成，无需再提供代理用于本轮检查。直连与该代理都不能登录同一行情端点，不能通过修改请求字段或增大本地等待解决。最终状态记录于 conclusion-final.json：客户端恢复逻辑通过验证，线上采集尚未恢复；外部服务/网络路径的具体故障原因仍需服务端进一步确认。
