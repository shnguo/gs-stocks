# 上涨初期评分的匹配增量检验

## 目标

判断上涨初期评分是否包含原模型预测以外的收益信息，而不只是在回避高波动和追高风险。

主规格在同一信号日、同一市场板块内进行一对一匹配，并控制：

- 原模型预测收益的截面排名；
- 截至信号日的二十日历史波动率排名；
- 截至信号日的二十日平均成交额排名。

处理组为上涨初期评分前百分之二十、价格位于右侧并且评分大于零的股票。对照组来自评分后百分之五十。匹配阶段不会读取未来收益。

## 冻结决策规则

只有主规格同时满足以下条件，才训练上涨初期辅助预测头：

- 至少五十个成熟信号日和一千个已知配对；
- 平均首日开盘可执行收益差为正；
- 超过百分之五十的日期收益改善；
- 平均不利波动不变差；
- 预测、波动率和流动性三个排名的最大平均绝对差不超过 0.05。

差日期收益和不利波动单独判断。它们改善时，可以保留风险筛选价值，但不会因此把评分写入模型训练目标。

## 已实现

- scripts/token_early_stage_matched.py：历史或前瞻队列的一对一匹配、日期区块自助法和冻结决策。
- scripts/verify_token_early_stage_matched.py：隐藏未来结果后独立重建配对，并重算全部汇总和每日指标。
- scripts/publish_daily_early_stage.py：每次手动日报保存小型 matching-cohort.csv，包含预测时可见的匹配变量。
- scripts/review_daily_early_stage.py：仅在 T 加 4 成熟后附加结果；未知行情保持未知，不做填充。
- configs/token-early-stage-matched-v1.json：原 71 日期历史重放协议。
- configs/token-early-stage-matched-prospective-v1.json：手动日报前瞻积累协议。

手动日报脚本没有增加定时任务。模型检查点、主排名和线上指针没有被修改。
