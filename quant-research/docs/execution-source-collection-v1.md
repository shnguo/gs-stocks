# 真实成交来源采集

2026-09-30，已接入并实测 Rust 来源采集器。研究侧仅编排请求、保存校验后的观察记录和生成部分证据包；Tushare 解析与金融字段校验由 mootdx-cf 的 Rust 模块负责。没有启动模型训练、交易、自动调度或部署。

## 本次实测

主榜和上涨初期榜各取前 20 名，去重后计划 40 只股票，共 82 个有界请求。实际请求 5 个：成功 2 个，拒绝 3 个，余下 77 个在接口失败后停止。

| 来源 | 实测结果 | 解释 |
| --- | --- | --- |
| stock_basic | 5,572 条当前股票记录 | 含行业；不证明历史上市身份完整 |
| stock_st | 权限不足 | 保存拒绝响应，未继续请求 |
| stk_limit | 权限不足 | 单股票、单日期请求；保存拒绝响应 |
| dividend | 一只股票的 37 条记录 | 第二只触发当前账户每分钟 1 次限制；随后停止 |

当前行业观察与冻结股票的上市日期及代码匹配后，形成 5,570 条当日覆盖记录。它们保留 9 月 30 日 10:39 上海时间的实际获取时刻，不能补成较早信号发布前的资料。本次没有生成正式成交快照，真实前瞻成交模拟仍为 0 个信号日。

接口说明：[股票资料](https://tushare.pro/document/1?doc_id=25)、[ST列表](https://tushare.pro/document/2?doc_id=397)、[涨跌停价格](https://tushare.pro/document/2?doc_id=183)、[分红记录](https://tushare.pro/document/2?doc_id=103)。ST列表当日更新时刻为 09:20，晚于榜单 09:15 截止。发布前判断与执行前风险复核需要分别保留可见时刻。

## 手动入口

在 mootdx-cf 中构建本地 Rust CLI。采集脚本默认使用 debug 二进制，保留现有 release 二进制与运行中的服务。

    cargo build --bin mootdx-cf-rs

在 quant-research 中小批量试采集。日期默认为当日上海日期；过去日期的获取时刻仍为实际采集时间。

    PYTHONPATH=src:scripts .venv/bin/python scripts/collect_execution_sources.py \
      --config configs/daily-token-v2.json \
      --workspace artifacts/daily-token-live-v2/execution-observations/NEW-DATE-v1 \
      --max-requests 4

默认最多 40 只冻结候选、82 个请求，每个新请求至少间隔 2 秒。每次手动调用最多发起 1 个新的分红请求。成功和失败响应均不覆盖；权限、连接或校验失败会停止该接口的剩余请求。相同工作目录支持精确恢复并验证归档血缘。请求范围、候选摘要或二进制改变时必须使用新目录。失败请求不通过恢复自动重试，也不切换令牌规避限制。

输出包含原始响应、范围与时间信封、Rust归一化记录、生产代码归档、覆盖记录、部分 canonical 表及公开回执。公开摘要只含来源地址、获取时间、计数、状态和哈希，不含凭证、私有路径或完整提供方错误消息。

采集后登记最新观察回执。研究刷新命令使页面显示它；新部分证据必须显式导入，不自动替换已登记的完整成交证据。

    PYTHONPATH=src:scripts .venv/bin/python scripts/review_daily_research.py \
      --store artifacts/daily-token-live-v2 \
      --execution-evidence OBSERVATION-BUNDLE \
      --output ../stock-indicator-dashboard/public/research/latest.json

## 验证边界

1. 当前股票不等于历史股票池完整证明。代码复用、上市日期不匹配或已退市记录不会获得行业覆盖。
2. ST观察只覆盖明确出现且有当前身份对应的 ST 股票。空列表或未出现的股票不自动解释为风险正常，交易所级正常覆盖保持未知。
3. 涨跌停记录只合并到已有同股票、同日期 OHLC 行；不会生成缺少价格的行情行，也不证明行情和复权因子完整。缺少行情时单独留存观察。
4. 分红接口不覆盖全部公司行动、配股或持有人条款。分红观察不生成正式行动或“无事件”证明。
5. 本地观察可见时刻等于获取时刻。较晚采集不能改变旧报告发布时间、匹配冻结时间或前瞻资格。合成基础输入仍保留合成标识。
6. 嵌套原始信封、归一化信封和生产代码也受哈希保护。改动归档会使登记验证失败，必须生成新版本。

下一步仍需可用的 ST 与涨跌停权限或同等来源，以及公司行动条款、正式规则与费用、正常风险覆盖、身份交叉核验和完整行情。研究页分别显示来源采集进展与正式成交验收。

## 验证结果

Rust 来源库 199 项测试通过；新增接口的 12 项针对性测试在最后修改后再次通过。来源库与实际 CLI 的 Clippy、变更文件格式检查及 CLI 构建通过。研究侧最终全量 388 项测试、44 项针对性测试通过，前端 39 项测试、构建和研究页 ESLint 通过。真实浏览器验证了采集计数、权限及频率状态、来源详情展开，桌面及 390 像素页面均无横向页面溢出，页面无控制台错误。

全仓库检查仍有原有问题：前端 TypeScript 的 8 项错误位于 realtime-ticket、market-data-env、首页、db 和 worker；Rust 全目标 Clippy 的 2 项错误位于 local-compute-runner；全仓库格式检查提示 d1_http 的既有导入布局。这些文件未因本次来源接入而修改。变更仍在本地，未提交或部署。
