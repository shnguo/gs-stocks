# 全自动公告验收：原生PDF第二路径的固定检验

本轮有效结论：MuPDF原生文字与位置可以改善第二提取路径，但尚未解决财务口径识别的覆盖问题。保持原金融规则不变，开发期原100份双路一致且算术通过数由OCR的13份增至20份；上批20份由1份增至3份。冻结后另取预先声明的新20份、41页，6份一致且双方算术通过，1份字段冲突被自动拦截，13份因至少一条提取路径不支持而跳过。当前没有取得正式交易信号或收益优势结论。

用户确认的20万元、佣金万分之五、最低5元和无需人工参与继续适用。系统遇到不支持、冲突或证据不足时自动拒绝并保存原因，不生成待人工填写任务。100个成熟公司×报告期事件、60个成熟入场日、504日唯一正式检验及120日运营检查沿用v3研究协议；10%回撤仍为研究假设，券商完整费用口径仍未核实。

## 实现与验证安排

主路径沿用Poppler文本与原Rust提取器。新第二路径由MuPDF 1.28.5输出结构化XML，Rust读取Unicode字符及四角坐标，生成逐页文字和字符位置，再交给原第二金融解析器v4。第二金融解析器与上一轮冻结版本的源码哈希完全相同，不读取主路径候选。MuPDF支持结构化XML输出，见[官方说明](https://mupdf.readthedocs.io/en/latest/tools/mutool-draw.html)。本地新增免费mupdf-tools工具，没有新增付费数据权限。

原始XML、工具版本与哈希、命令回执、文字及坐标、PDF身份和实际本地获取时钟均保存。比较入口重新从XML生成派生内容并逐字节核对；仅重写派生文件及其哈希不能通过。原生字符没有OCR置信度，记录为不可用。旧第二解析器的ocr诊断字段名为兼容名称，本次原生路径并未执行OCR。

在开发样本上，初版适配器错误拒绝MuPDF输出的零高度空格。保留初版原件及比较结果，修正为允许空格的退化坐标；可见字符的非法几何、未知实体、非有限坐标、不支持的文字方向及页码错序仍拒绝。开发100份中有2份含零高度的私用区字符，保持整份拒绝，没有猜成空格。金融金额、单位、报告期和收益门槛未作调整。

原100份和上批20份均归为本轮开发资料。另从既有1640条索引中排除135个本地PDF公告身份，按来源日期、公告ID和证券ID固定下一批20份，来源日期声明为2026年7月6日至8日。声明和下载发生在读取财务内容之前，下载及解析失败不换样。使用既有原始分页的较晚重新观察，不重查旧失败窗口，也不把7月的来源日期当成本地历史及时获取证据。

实际UTC 2026-10-13 07:10:26冻结13份生产源码/依赖文件、程序及MuPDF、pdftotext、pdfinfo三个工具。随后才生成新20份文本、主候选、第二路径和比较结果。新结果出现后没有改动冻结实现。两次独立审计均确认样本、源码、程序、工具及时间顺序。新批与先前120份开发PDF无字节重复。

新20份全部完成原生解码。主路径得到17份候选，第二路径得到7份候选，其中6份一致的原文披露同比下限均达到30%。这些仍只是未取得资格的候选，不能直接转为订单。

原100份的3个冲突均发生于基期金额，第二路径比主路径高100倍；新20份的1个冲突发生于披露同比，第二路径也比主路径高100倍。这是实际拦截到的数量级差异。系统没有用主路径答案修正第二路径，没有取更有利的数值，也没有将本轮新样本的结果用于调整规则。

新20份第二路径拒绝原因按程序诊断为：归母利润标签未定位6份，表头缺失或多重2份，数值数量歧义1份、数字分组异常1份、基期单元格不唯一1份、同比方向歧义1份、表格亏损不属于当前主假设1份。这是程序可处理范围的诊断，并非原公告内容错误的断言。

6/20表示这批固定样本的双路一致覆盖比例，不是准确率。它与上批OCR的1/20来自不同公告，不能声称六倍提升；可直接配对的开发结果为13→20及1→3。开发样本已参与调试，另20份也不是全市场随机样本，不能合并为140份独立泛化检验。不同PDF解码器减少一项共享依赖，但原始PDF、开发过程、规则设计及部分库仍共享，多路一致没有提供真实答案或盈利证明。

因此，继续投入最有价值的工程方向是：保留原生位置路径，按已保存失败原因改善表格语义与单位/小数识别，并继续在事先固定的新原件上验证；同时补齐历史ST、停复牌、涨跌停、公司行动日期、完整公告版本链和实际可见时间。这些来源与正式运行器完成后，才可验证事件策略扣费后的收益优势。不能用少数容易读取的模板替代原研究范围，或据此提前启动504日正式计时。
