# 云端自动恢复与多源补缺

本次实现保留完整 A 股计划、全部 11,624 个原始任务身份和已有入仓回执。采集仍由 Cloudflare Container 中的 Rust 执行，D1 保存调度状态，R2 保存不可覆盖的原始证据，R2 Iceberg 保存来源记录。

## 故障隔离与恢复

网络超时、连接中断、临时不可用和源端 5xx 进入延迟重试。每个任务最多执行 6 次，间隔为 30、120、600、1800、3600 秒，附带少量错峰。已成功的任务不会重新领取。每次请求开始前先写独立尝试记录，上传原始归档并下载核验后才写完成回执。

连续 3 次瞬时失败使该提供方的该接口进入冷却，其他健康接口继续，已采集记录继续发布。初次冷却 5 分钟，探测再失败延长为 15 分钟、60 分钟，上限 60 分钟。探测只查询固定证券的一个交易日，原始证据独立归档。探测成功自动恢复健康状态。旧请求晚到的成功回执不能自行清除冷却。

冷却期间没有可执行任务时，协调器释放租约；批次保持 active，Cloudflare 每分钟调度会继续检查到期探测及延迟任务。人工暂停不会被自动恢复。

明确的权限和配额拒绝仅禁用对应接口，保留人工处理入口。已有 Tushare 复权因子账号限制保留，不推断该限制适用于日线。原始归档完整性、D1/R2 归档故障或租约丢失仍然暂停批次。数仓临时错误现已增加持久重试，永久错误或耗尽重试次数才暂停，详见 [数仓临时故障恢复](cloud-warehouse-retry-20260908.md)。进程中断且未取得持久回执的任务继续保留审查状态。

## 多源路由与质量

日线备用适配器包括 Tushare 和东方财富。备用查询由原始任务派生，必须保持同一股票、起止日期和未复权日线范围；因子不允许借用日线路由，也不混接不同来源的复权曲线。

备用来源默认关闭。POST /qualify 在实际 CF Container 上执行固定样本对账：沪深京、长历史、历史 ST、退市、改码/长期停牌及新上市短历史。比对有效交易日集合和开高低收、成交量、成交额。报价容差 0.00001，成交量容差 max(1 股, 5e-8 相对误差)，东方财富整数手报价采用 max(50 股, 5e-8 相对误差)，成交额容差 max(1 元, 1e-6 相对误差)。接口截断风险、空日线、错误股票或日期范围、重复日期会被拒绝。

初次严格对账结果完整保留。原件核验显示 Tushare 样本成交量差异最多约 8 股、相对差异不超过 2.7e-8；东方财富样本整数手报价差异最多 50 股。精度差异写入结果，不修改原始数值。POST /requalify 可使用已归档、查询身份匹配的相同响应重新验证，不再次请求数据源。

按来源和交易所分别保存验收结果及 R2 证据地址。同一交易所至少两个样本且全部通过才能启用该备源。原始来源失败或冷却时，合格健康备源接管失败/待采日线，优先 Tushare，再东方财富。样本验收不等于全历史完整性验收。全量交易日、停牌、历史身份、ST 和公司行动仍需后续规范层检查，训练门槛继续关闭。

## 进度与运维

GET /status 继续返回原任务完成量、入仓行数与最近运行，新增来源健康状态 sources、待重试数量及最近到期时间 retries、备用资格 qualifications 和云端验收记录 validations。

research_jobs 代表原计划需求，进度按该表计数。research_attempts 代表采集、探测和验收尝试，保留每次来源、查询、错误类别、耗时、R2 地址。多个来源成功不会重复增加原计划任务总数。

research_source_health 保存接口冷却和禁用状态。research_source_qualifications 保存经过对账的来源/市场组合。原 research_capture_metrics 继续保留作为历史记录，其历史指标已复制到尝试表。

POST /recover 仅用于迁移本次旧版本的“连续三次源端失败”暂停：只将有归档证据的已知网络错误转入延迟重试，并保留失败快照。该入口不接受存储或其他未知错误。恢复后先保持人工暂停，配置小批量验证再启动。运行中的正常重试不需要调用该入口。

POST /configure、/start、/pause 继续使用现有鉴权与租约边界。POST /qualify 仅能在暂停且租约已释放时执行。所有新入口均由 Rust 执行操作，Worker 负责鉴权和转发。
